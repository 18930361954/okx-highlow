# 自愈功能完善方案

## 一、现状分析

### 1.1 现有自愈机制

#### 启动时自愈（startup_orphan_scan + daily_db_heal）
- **位置**：`execution/reconciler.py:1360-1403` + `core/daily_db_heal.py`
- **触发时机**：
  - 启动时：`startup_orphan_scan()` 扫描重复 algo 单
  - 启动时：`daily_db_heal()` 深度对账历史持仓
- **功能**：
  - 扫描 pending algos，相同 clOrdId 只保留最早的，撤掉重复单
  - 回填 OKX 历史持仓到 db（RECOVERED 标记）
  - 余额对账，同步 OKX 真值

#### 运行时自愈（reconciler 20s 轮询）
- **位置**：`execution/reconciler.py:run_once()`
- **触发时机**：每 20s 轮询一次
- **功能**：
  1. **entry 匹配**：db open trade 匹配 OKX filled orders
  2. **exit 匹配**：db 已入场 trade 匹配 OKX 平仓订单
  3. **孤儿单检测**：
     - `_cleanup_duplicate_pending`：同 pair 重复 pending 撤晚的
     - `_sweep_zombie_open`：db open 但 OKX 已不在 pending 且信号桶已过期
  4. **保护检查**（每 5min）：
     - `_protect_open_trades`：检测活仓是否有 TP/SL 保护
     - OCO 触发后未成交导致保护消失 → 重挂 OCO
     - 触发价已越线 → 收敛到现价±0.2% 或市价平仓
  5. **补挂逻辑**：
     - `_catchup_after_exit`：平仓后立即补挂新信号（比整点快 ~20s）

#### 定时自愈（daily_db_heal 每日 23:50）
- **位置**：`main.py:424-438`
- **触发时机**：每天 23:50 UTC
- **功能**：深度对账所有账户的历史持仓

### 1.2 已知欠缺点

根据今天的问题（8 个孤儿单），现有机制的欠缺：

#### 问题 1：OKX 模拟盘数据保留期短
- **现象**：`refill-fees` 回拉历史订单时，191 条全部显示"OKX 未找到相关数据"
- **原因**：OKX 模拟盘历史订单 API 保留期很短（<7天？）
- **影响**：无法通过 API 补拉旧订单的 fee/pnl 详情
- **解决**：依赖 `daily_db_heal` 的持仓级对账（不依赖订单详情）

#### 问题 2：孤儿单检测有时间窗口
- **现象**：algo 单触发后，持仓已平，但 algo 单状态仍是 `live`
- **原因**：OKX algo 单触发后不会立即变成 `effective`/`canceled` 状态
- **影响**：reconciler 无法通过 algo 状态判断是否孤儿
- **当前方案**：`_protect_open_trades` 检测活仓无 TP/SL → 重挂

#### 问题 3：手动平仓或异常清算无法实时感知
- **现象**：持仓被 OKX 清算或手动平仓后，db 记录仍是 open
- **当前方案**：reconciler 20s 轮询 `_match_exit` 检测平仓
- **欠缺**：如果程序停止运行期间发生清算，重启后才能感知

#### 问题 4：网络故障期间数据漂移
- **现象**：reconciler 网络异常时跳过当轮对账
- **当前方案**：下一轮自动重试
- **欠缺**：长时间网络故障（>1小时）可能积累多个未匹配订单

#### 问题 5：余额漂移无主动修复
- **现象**：充值/提现导致余额漂移
- **当前方案**：
  - 挂单前 `_sync_balance_before_place` 同步
  - 启动时 `daily_db_heal` 同步
- **欠缺**：运行期间充值/提现需等到下次挂单或重启才同步

#### 问题 6：缺少主动健康检查
- **现象**：没有周期性全量对账
- **当前方案**：仅启动时 + 每日 23:50 深度对账
- **欠缺**：白天运行时数据漂移无法及时发现

#### 优化 2：余额主动同步
- **目标**：运行期间充值/提现立即生效
- **方案**：每小时同步一次余额（无持仓时）
- **实现**：新增 `hourly_balance_sync` 任务

```python
def hourly_balance_sync():
    """每小时同步余额（无持仓时），吸收充值/提现"""
    for rt in ok_runtimes:
        try:
            held_pairs = _pairs_with_open_position(rt.okx, rt.logger)
            if held_pairs is None or len(held_pairs) > 0:
                continue  # 查询失败或有持仓时跳过
            _sync_balance_before_place(rt, held_pairs)
        except Exception as e:
            rt.logger.warning(f"[hourly-balance-sync] 失败: {e}")

sched.add_job(
    hourly_balance_sync,
    trigger=CronTrigger(minute=5, timezone=UTC),  # 每小时 05 分
    id="hourly_balance_sync",
    misfire_grace_time=600,
    coalesce=True,
    max_instances=1,
    replace_existing=True,
)
```

#### 优化 3：网络故障恢复后主动对账
- **目标**：网络恢复后立即补齐漂移数据
- **方案**：reconciler 检测到网络故障恢复时，触发一次 mini heal
- **实现**：在 `reconciler.py` 添加故障恢复检测

```python
class Reconciler:
    def __init__(self, ...):
        ...
        self._net_ok = True  # 上一轮网络状态
    
    def run_once(self) -> None:
        current_net_ok = not self._net_fail_ts
        if not self._net_ok and current_net_ok:
            # 网络从故障恢复 → 触发 mini heal
            if self.logger:
                self.logger.info("[reconcile] 网络恢复,触发一次深度对账...")
            self._mini_heal()
        self._net_ok = current_net_ok
        ...
    
    def _mini_heal(self) -> None:
        """轻量级深度对账：只对账当前活仓 + 最近 24h 历史"""
        from core.daily_db_heal import sync_positions_from_okx, reconcile_balance
        try:
            sync_positions_from_okx(
                self.account, self.db, self.okx, self.logger,
                days_back=1,  # 只回溯 1 天
            )
            reconcile_balance(self.account, self.db, self.okx, self.logger)
        except Exception as e:
            if self.logger:
                self.logger.warning(f"[mini-heal] 失败: {e}")
```

### 2.3 中期增强（1 周内）

#### 增强 1：孤儿单检测增强
- **目标**：更快检测 algo 单触发后持仓消失的情况
- **方案**：`_protect_open_trades` 增加持仓校验
- **实现**：检测 db open trade 但 OKX 无持仓 → 立即标记 exit

```python
def _protect_open_trades(self) -> None:
    """保护检查：活仓必须有 TP/SL，且 OKX 持仓必须存在"""
    ...
    for tid, a in to_check:
        pair, side = a.get("pair"), a.get("side")
        ...
        # 新增：校验 OKX 持仓是否存在
        okx_pos = None
        for p in positions:
            if p.get("instId") == pair and str(p.get("posSide") or "").lower() == side:
                okx_pos = p
                break
        
        if okx_pos is None or float(okx_pos.get("pos", 0) or 0) == 0:
            # OKX 持仓消失，但 db 仍 open → 触发强制平仓匹配
            if self.logger:
                self.logger.error(
                    f"[reconcile] [protect] trade#{tid} {pair} {side} "
                    f"db 显示活仓但 OKX 无持仓 → 触发强制退出匹配"
                )
            try:
                self._force_match_exit_from_history(tid, pair)
            except Exception as e:
                if self.logger:
                    self.logger.warning(
                        f"[protect] trade#{tid} 强制匹配失败: {e}"
                    )
            continue
        ...
```

## 五、风险评估

### 风险 1：频繁对账影响性能
- **概率**：低
- **影响**：中
- **缓解**：每 4 小时一次，单次耗时 <5s，可接受

### 风险 2：余额同步误操作
- **概率**：极低
- **影响**：高
- **缓解**：仅在无持仓时同步，安全性高

### 风险 3：网络故障恢复检测误触发
- **概率**：低
- **影响**：低
- **缓解**：mini_heal 仅回溯 1 天，成本可控

## 七、总结

现有自愈机制已经比较完善，主要欠缺在于：
1. **检测窗口长**：仅每日 23:50 深度对账
2. **余额同步被动**：仅挂单前同步
3. **网络故障恢复慢**：无主动补偿机制

本方案通过增加日间健康检查、主动余额同步、网络故障恢复对账，可以将数据漂移检测窗口从 24 小时缩短到 4 小时，大幅提升系统健壮性。

优先实施 P1 方案（日间健康检查 + 余额同步），可以在不增加复杂度的前提下，显著改善自愈能力。
